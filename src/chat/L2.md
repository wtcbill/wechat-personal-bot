# L2 — chat 问答与搜索

上层入口：[L1](../../L1.md)。chat 是可独立调用的后端服务；搜索属于其内部能力。目前可通过本机 CLI、公共接口，或终端／微信 routed 的 [服务路由](../router/L2.md) 装配调用。后者已通过真实 API 的问答、追问及搜索／原文读取受控样本验收；微信真实问答与搜索回复也已由用户确认手机收到。

## 边界与契约

- 实现 [BackendService](../services.ts)：`run({sessionId, requestId, text, network?}, signal)`。调用方提供本服务的会话与请求标识，负责访问控制、服务选择、路由绑定、发送和送达恢复。chat 不导入 iLink，不选择 DSH／Codex，不发送消息。
- 返回 `status`（completed／limited／failed／cancelled）、`answer`、`sources` 和 `limitations`；`ChatResult` 另含逻辑调用次数和工具执行记录。结果不含密钥、供应商异常正文或完整网页正文。
- 注入独立的 `ChatModel`、`SearchProvider` 接口。当前装配为 DeepSeek；同一 Chat 模型分检索与作答两个阶段，`ModelRequest.thinking` 按次传入。Chat、Search、Fetch 各自请求，工具不额外调用分类模型。
- 未传 `network` 时默认 `auto`，由现有检索模型结合真实意图、上下文、时效与事实不确定性决定搜索、作答或澄清；程序不从自然语言关键词改写策略。模型区分操作要求与引用／翻译对象；auto 下明确要求不搜索时，检索不搜索／抓取，作答也不请求补查。`off` 由调用方显式传入，程序禁止搜索／抓取，仍需要 Chat API；`required` 要求本轮实际外部证据，缺关键条件时允许简短澄清。各入口参数见 [README](../../README.md#chat-本机问答与搜索)。

## 执行与失败边界

1. 检索阶段关闭思考，决定是否搜索、搜索什么、读取／查找哪些资料；通过 `search_web`／`read_source`／`find_in_source` 取得结果后继续决策。结束时只返回 `{"action":"answer"}` 或 `{"action":"clarify","missing":"缺少的条件"}`，不生成用户答案。非法决定可有限修复；未知工具、参数错误、未登记来源、未读取正文均回传结构化错误。
2. Search 查询串行执行，URL 去片段后去重；保留来源编号、标题、摘要、发布时间、获取时间和状态。检索目录透传本轮真实 unread／summary／read／failed 状态；read 表示正文已缓存，不保证模型已读完整页。读取只能使用已登记 URL；用户文本中的有效 URL 自动登记。正文缓存供分页读取与字面查找使用，截断后未匹配不代表原网页没有内容；新问题仅重登历史来源元数据并从 unread 开始，同轮补查沿用已有状态。
3. 检索结束后构造独立的作答上下文：原问题、有限问答历史、实际来源、工具返回的摘要／正文片段／查找结果／错误。检索阶段的自然语言草稿和工具调用消息不带入。作答调用开启思考（当前 high），不提供工具；先检查资料是否足够，再返回严格 JSON：`{"action":"answer","answer":"用户回复"}` 或 `{"action":"supplement","missing":"待核实的关键事实"}`（缺口至多 600 字符）。直接回答、澄清与预算收尾也走此阶段；只从 `content` 解析决定，不保存或输出 `reasoning_content`，公共结果和会话历史仅保存最终用户回复。
4. 思考阶段最多返回检索阶段一次。程序验证补查决定、联网策略、剩余模型／工具预算与原检索截止时间后，把缺口交给关闭思考的检索阶段决定查询与阅读；复用同一来源、正文缓存和预算。一次返回可以包含受原预算约束的搜索／阅读／查找循环，不等于只调用一次 Search API。之后重新把两次实际资料合并交给思考作答，不携带先前思考草稿。再次请求补查、禁止联网或预算不足时不执行；补查失败或空结果加入限制，有剩余时间和调用次数时仍完成思考收尾。资料仍不够时说明缺口或澄清。
5. 工具次数、搜索／抓取次数、所有阶段合计模型轮次、上下文字符量和整轮时间共同设限；为思考收尾预留时间和至少一次调用，检索与作答分别设置输出 token 上限。补查不重置时间／次数，只有思考返回后仍够至少一次检索调用和一次作答调用才执行。运行默认值以 [service.ts](service.ts) 的 `DEFAULTS` 为准，可用构造参数调整；真实受控样本通过，广泛任务的预算校准尚未完成。适配器的普通与思考请求分别设超时，仍受整轮取消与时间预算限制；有限 HTTP 重试不重置预算。
6. 已返回的工具调用逐个补结果；截断的工具批次、非法或截断的补查决定不执行。思考阶段直接返回的工具调用仍被拒绝。取消不触发新模型调用，思考作答失败不回退到检索草稿。上下文满时停止扩大输入，无法容纳作答资料时返回受限说明。
7. 输出检查决定格式、引用 ID、URL 归属、显式搜索要求及长度；URL 比较复用来源登记的 webUrl 规则，忽略 fragment，原答案保留页内锚点；不同协议、主机、路径或查询参数仍须有本轮来源，不验证锚点存在。修正仍开启思考且不提供工具，至多两次。未用过的补查机会可在修正中提出，仍受相同检查。协议 JSON、未通过检查的草稿不返回用户。引用 ID 与来源保留供内部核验，作答提示词禁止额外罗列来源清单；用户明确索要时仅给相关出处／链接。共享格式化隐藏内部引用标记、停止自动附加全部来源；独立 CLI 复用同一格式化。程序不证明证据在语义上支持结论，也不保证模型发现全部资料缺口，需真实样本人工检查。

## 内存与并发

- 最多 20 个会话，每个保留至多 8 轮、20,000 字符的问答；会话空闲 30 分钟后在下一次请求时清理。网页正文每来源最多缓存 40,000 字符，读取每页 8,000 字符。当前轮结束即释放正文，仅保存有限问答与来源元数据；后续轮引用旧来源须重新获取。
- 最多 8 个任务同时运行，同会话串行。重复的会话／请求 ID 及相同内容共用一次执行，返回独立结果副本；相同 ID 改内容会拒绝。第一次调用的取消信号控制共享执行，重复调用者不能独立取消它。
- 结果最多缓存 100 项、30 分钟（请求时清理），失败／取消结果也保留；外层可以重取已有答案处理发送恢复，不能无限期依赖缓存或保证跨重启恰好一次。主动重试应使用新的请求 ID。
- `clearSession` 仅清历史和来源，不清请求去重记录；正在运行时返回 false。所有 chat 状态重启清空，不写文件或 SQLite。路由与渠道状态不归本模块。

## 接口依据

2026-10-21 按官方 [Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)、[Tool Calls](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)、[Search](https://api-docs.deepseek.com/zh-cn/api/search/) 和 [Fetch](https://api-docs.deepseek.com/zh-cn/api/fetch/) 核对请求与响应。默认模型为可配置的 `deepseek-flash`；当前检索关闭思考、最终作答开启思考，未提供 CLI 模式开关。思考阶段不携带工具，重新构造资料上下文，避免跨模式沿用工具调用历史。2026-10-22 实际 Chat／Search／Fetch 均返回 HTTP 200，并完成思考作答与引用。结论限于当次受控样本；微信普通问答与搜索回复已实测送达；补查、异常边界、更多任务的搜索质量及长回复分段仍需各自验收。
