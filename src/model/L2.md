# L2 — 共享模型适配

上层入口：[L1](../../L1.md)。从原 chat 适配器提取供路由和 chat 共用的模型消息、HTTP 与补全能力；模型实例按业务分别构造，配置与上下文分开。

- [types.ts](types.ts) 提供 `LanguageModel`、消息／工具／思考参数、模型返回与安全错误；不管理任何路由或对话历史。
- [deepseek.ts](deepseek.ts) 的 `DeepSeekModel` 接收显式 key／model／超时和可注入 fetch，`complete` 执行 Chat Completions，`post` 提供供应商固定主机的底层 HTTP。没有从环境自动读取密钥或在构造时发请求。
- 仅请求固定 `https://api.deepseek.com`；拒绝重定向，响应最多 2 MB，校验消息／工具／完成原因。可重试 HTTP／网络失败受限重试，认证失败不重试；取消不重试。具体上限与默认值以源码为准。
- 路由装配显式关闭 HTTP 自动重试并共用路由截止时间；chat 保留既有普通／思考超时及整轮预算。Search／Fetch 的输入、响应与业务工具仍在 [chat](../chat/L2.md)，通过共享 HTTP 发送。
- chat 的旧类型入口保留再导出，模型错误在 chat 适配边界转成 `ChatError`，不要求原调用方改为共享错误类型。

[真实 API 验收](../verify-api.ts) 已验证路由、chat 分阶段思考及 Search／Fetch 的实际调用。配置与决定解析分别由纯逻辑测试覆盖；所有模拟 HTTP／模型测试已按用户要求删除。真实验证结论限于受控样本，未覆盖全部异常边界。
