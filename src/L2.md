# L2 — 应用与启动

上层入口：[L1](../L1.md)。应用仅保留真实服务处理，早期固定回复诊断已移除。终端默认经 [服务路由](router/L2.md) 调用真实 [chat](chat/L2.md)；直接问答、连续追问及搜索／读取后的思考作答已通过真实 API 受控样本验收。iLink 普通启动即装配相同真实服务，旧 `--mode routed` 参数兼容；用户此前已确认手机问答与搜索回复正常。

## 职责、契约与状态

- `InboundText` 提供消息标识、发送者、文本及不透明回复句柄；`TextChannel` 提供接收、回复、释放句柄和游标检查点。`receive` 返回空数组时继续接收，返回 `null` 表示输入结束、正常退出应用循环。应用不读取微信协议字段或模型 SDK 对象。
- 应用使用启动装配提供的本人身份：正常模式由渠道登录确定，调试模式使用终端渠道的本地调试身份。`Application` 接受本人非空文本，调用注入的公共请求处理器。
- 每个应用实例生成独立应用会话 ID，请求 ID 来自渠道消息 ID；服务路由再映射为后端会话。同条消息不重复执行或发送，ID 对应内容变化会记录冲突。应用记录最多 100 条，完成后保留 30 分钟，容量满时淘汰已完成记录；重启清空。
- 应用分别保留后端结果、已格式化分段、已发送段数及 processing／ready／accepted／submitted／failed_or_unknown／cancelled 状态；`delivery(messageId)` 返回副本。分段失败后保留已有结果，不自动重跑后端或重发未知结果；人工重发交互尚未实现。缓存范围外不承诺严格恰好一次。
- 渠道返回统一发送回执：iLink 的 `accepted` 为接口明确成功，`submitted` 为提交完成但无明确成功码；均不代替手机实际送达确认，后者也不触发自动重发。终端渠道在输出写入完成后返回 `accepted`，只代表本地输出完成。
- 一批消息按顺序处理后才请求渠道保存游标。普通接收失败退避，认证失效退出，取消信号传递至处理器、渠道与等待。首版串行处理，没有跨会话任务队列；处理期间 Ctrl+C 可取消，`/exit` 会在当前消息结束后处理。
- 所有 start 命令均装配真实 API；`--debug` 使用终端，普通启动使用微信。`--mode routed`、`--backend api` 仅兼容旧命令，其他模式／后端参数拒绝。真实服务配置在进入微信登录／锁之前检查；固定回复诊断、模拟模型和模拟后端均已删除。
- API 密钥优先级为角色内 `apiKey`、共享 `apiKey`、命名环境变量。用户可在忽略提交的 `services.config.local.json` 填一次共享 Key，路由与 chat 共用；公开样例保留空值。`api-check` 会读取本机文件，仅输出模型等非密钥信息，解析／校验失败不回显文件内容。check／login 不加载服务 API 配置。
- `ConsoleChannel` 按行读取终端，非空普通行转为带唯一消息 ID 的 `InboundText`；回复句柄仅在处理期间有效，释放后拒绝发送。`/exit` 和 EOF 结束输入，EOF 前已缓冲的行依序处理；取消会关闭等待中的读取。终端 Ctrl+C 传给应用的取消控制器。
- 终端仅承担收发适配，不复制应用或服务逻辑；无文件、微信状态、网络与持久游标。调试启动不加载微信配置；服务通过真实后端联网。命令见 [README](../README.md#路由调试与-api-配置)。
- `formatReply` 统一呈现答案和必要限制，保留内部来源校验，默认不追加来源列表并隐藏已登记的 `[S数字]` 标记；正文中明确提供的链接保留，按 Unicode 字符分段；后端执行／结果格式异常转换为安全失败文本。格式化不调用模型，发送由应用经 `TextChannel.sendReply` 完成。当前分段是定长文本切分，超长 URL／表格等丰富内容的排版尚未专门优化。
