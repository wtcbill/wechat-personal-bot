## 2026-10-19：消息链路、上下文与 harness 讨论

### 源码确认

- 当前入口调用 `wcferry.Wcf(debug=False)`。上游 WeChatFerry SDK 使用 DLL 注入；本会话没有实际启动这一接入。
- 消息链路：接收队列 → 过滤私聊文本 → 按发送者与消息 ID 去重 → 命令或对话处理 → 模型调用 → 保存问答 → 分段发送原发送者。
- 当前历史仅存内存，默认保留最近 20 轮；每次请求发送系统提示词、保留的历史及新问题。模型调用失败不追加该轮历史，发送失败时历史可能已经保存。
- 当前模型客户端支持 Ollama 和兼容 Chat Completions 的文本请求，未读取 token 或缓存用量。

### 讨论形成的认识

- 重发历史与提示词缓存可以同时存在；是否享受缓存价格取决于服务商、模型及实际命中。尚无真实接口用量数据。
- 缓存未命中影响计算和费用；历史裁剪、重启清空和超出窗口是不同问题。
- 讨论了现代 harness 的持久记录、按 token 组织上下文、压缩、历史检索、工具循环和恢复。没有实施上述能力。
