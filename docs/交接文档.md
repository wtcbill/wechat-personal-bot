更新日期：2026-10-23（日本时间）。v0.1 本人自用首版核心功能完成，用户已确认最新修复版本的手机端复测完成，进入日常使用。本文只维护当前接续；详细工程／API 验证见 [修复验证记录](archive/首轮审查修复验证_2026-10-23.md)，过程与历史见 [项目日志](项目日志.md)。仓库版同步到父工作区并按位置调整链接。

## 1. 目标与入口

Weave 以微信聊天作为自然语言入口，经独立 AI 服务路由调用后端；当前只接入 DeepSeek chat。实际仓库为原工作区中的 Weave 子目录，当前分支 main。旧实现独立保留，不参与续建。

文档从 [目录索引](README.md) 进入；先读适用的 [工作须知](工作须知.md)、[仓库规则](../AGENTS.md) 和 [L1](../L1.md)，再按任务进入模块。产品范围见 [首版方案](首版方案.md)，技术选择见 [技术栈](技术栈.md)，模块分工与流程见 [架构草案](架构草案.md) 和 [chat 方案](Weave搜索问答方案讨论.md)。历史材料只按需追溯。

在 Weave 目录启动：

```powershell
npm.cmd start
npm.cmd start -- --debug
```

普通启动运行真实微信问答，--debug 使用终端；旧 --mode routed／--backend api 仅兼容。固定回复诊断和模拟实现已删除。配置、退出与全部命令以 [README](../README.md) 为准。

## 2. 当前能力与边界

- 已接通 微信／终端 → Application → ServiceRouter → ChatService → 公共结果与格式化 → 渠道回复。路由独立理解意图，chat 内部决定搜索／阅读／澄清，不通过 chat 业务循环做外层分类。
- chat 已实现检索关闭思考、作答开启思考、Search／Fetch、一次有界补查及有限内存多轮。B1–B4 和 required 澄清误拦截已修复；具体工具、协议、状态、预算与限制见 [chat L2](../src/chat/L2.md) 和 [router L2](../src/router/L2.md)。
- 应用保留本人限制、去重、格式化／分段及发送进度。部分发送失败保留结果，不自动重跑或重发；人工恢复交互尚未实现。所有应用／路由／chat 历史与结果均为有界内存，重启清空，不保证跨进程恰好一次投递。
- 当前微信入口是扫码绑定的 iLink 机器人会话，Weave 直接请求协议，不运行 OpenClaw 宿主；普通好友／小号渠道尚未实施。
- 本机服务配置使用被 Git 忽略的 services.config.local.json，共享 Key 与角色覆盖规则见 README；微信凭据和游标仅存本机 .weave。不从 Git 版本推断本机已配置或已登录，不打印或提交密钥与聊天数据。
- DSH／SSH 远端 Codex、其他后端、SQLite、服务器部署尚未实现；本人专用和内存历史边界保持。

## 6. 在另一台电脑继续

1. 克隆仓库或在已有副本执行 git pull --ff-only，核对分支、当前提交与工作树，再读 AGENTS、docs/工作须知、本文和 L1。
2. 运行环境和依赖以工程文件为准，安装／检查命令见 README；安装需要当前用户授权。默认测试不联网，真实 API 验收显式运行。
3. 在本机创建忽略提交的服务配置、填写 Key，并独立建立微信登录；先用 --debug 验证后端，再按需要启动微信。独立 chat CLI 的环境变量入口见 README。
