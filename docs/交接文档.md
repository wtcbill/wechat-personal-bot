## 1. 项目目标与开发入口

Weave 以微信聊天窗口为自然语言入口，远程调用自己的工具与服务。首个后端为 DeepSeek chat；DSH、SSH 远端 Codex 和其他后端后续接入。目标链路为：`微信／iLink → 应用 → AI 服务路由 → 所选后端 → 公共结果与格式化 → 渠道回复`。

阅读顺序：[工作须知](工作须知.md) → [仓库规则](../AGENTS.md) → [L1](../L1.md)，按 [GEB 指南](GEB使用与维护指南.md) 维护实际地图。[首版方案](首版方案.md) 维护阶段范围，[技术栈](技术栈.md) 维护技术选择，[README](../README.md) 维护运行入口。旧实现 wechat-personal-bot 独立保留，不在其中续建或搬动已有文件。

## 3. 已确认的架构边界

1. 上层服务路由独立调用 AI 判断自然语言意图并选择已注册后端，程序校验决定；意图不清先澄清，不默认广播或失败后自动换服务。
2. chat、DSH、SSH 远端 Codex 是并列后端。chat 内部管理对话历史、搜索决策、Search／Fetch、阅读／查找、证据与答案；路由不通过 chat 业务循环分类。
3. 路由与 chat 可共用供应商和底层模型 HTTP 客户端，但分别构造实例、管理提示词、上下文和状态。
4. chat 检索关闭思考，作答开启思考（当前 high）且无工具；直接回答和澄清也走思考作答。关键缺口最多返回检索一次，共用原联网限制、时间和调用预算。具体行为以 chat L2 和源码为准。
5. 微信协议、句柄和收发归渠道；访问校验、去重和回复协调归应用；公共回复格式化在 chat 外；后端会话映射归路由。
6. 应用、路由、chat 历史及结果均为有界内存，重启清空。iLink 凭据和收消息游标仅在本机保存；不能据内存记录承诺跨进程恰好一次投递。

后续五项方向统一见 [未来更新方向](../未来更新方向.md)：路由、chat 上下文、个人数据库／个性化、多用户和语音。讨论资料入口：[架构草案](架构草案.md)、[chat 方案讨论](Weave搜索问答方案讨论.md)、[历史搜索调研](DeepSeek搜索链路调研_2026-10-20.md)。调研结论不等于当前自建实现已全面优于官网。
