# Weave 技术栈

状态：基础技术栈已确认，当前实现已包含独立 chat、服务路由和终端／微信装配。本文维护技术选择；具体依赖版本以 [package.json](../package.json)、[package-lock.json](../package-lock.json) 和 [.node-version](../.node-version) 为准。首版功能与阶段验收见 [首版方案](首版方案.md)，最近验证见 [项目交接](交接文档.md)。

| 部分 | 已确定选择 | 落地约束 |
| --- | --- | --- |
| 主干语言 | TypeScript，strict 类型检查 | 应用、公共契约、微信与 DeepSeek 适配器统一 TS；允许未来工具使用其他语言 |
| 运行环境 | Node.js 24 LTS | 首先在本机 Windows 运行；当前开发版本由 .node-version 记录 |
| 包管理 | npm、精确的直接依赖版本、package-lock.json | 使用锁文件重现安装；依赖及 npm 缓存在项目内 |
| 工程检查 | TypeScript 类型检查与编译、Vitest 纯逻辑／实际终端测试；独立 chat 离线结构检查 | 显式真实 API 验收独立运行；原 chat Node 内置模拟测试已删除。源码使用可擦除的 TS 语法，可直接由 Node.js 24 启动，也可编译为 JS |
| 微信接入 | iLink HTTP 协议，由 Weave 的 TS 渠道适配器封装 | 当前使用 Node 内置 fetch；按腾讯公开协议验证所需文本能力；不依赖 OpenClaw 宿主 |
| 模型与检索调用 | Node 内置 fetch，调用 DeepSeek Chat／Search／Fetch HTTP API | HTTP／模型补全提取到 [共享模型适配](../src/model/L2.md)，路由与 chat 分别构造；搜索业务及 Search／Fetch 协议继续归 [chat](../src/chat/L2.md) |
| 服务路由 | 独立模型决定、程序严格校验、公共后端接口 | 真实路由到 chat 的问答、追问及搜索读取已通过受控样本；模型与密钥入口独立于 chat，见 [路由模块](../src/router/L2.md) |
| 持久化 | SQLite | 用于以后确需持久化的结构化状态；本阶段不建库。聊天历史仅放内存，重启清空 |
| 运行结构 | 单进程、内部模块与接口隔离 | 渠道、应用、API 对话能力、模型适配、回复格式化和启动装配分别承担职责；按实际功能建模块 |
| 登录状态 | 项目内 .weave 目录中的本地文件 | 保存登录凭据和收消息游标，与模型聊天历史分离；目录忽略提交，不记录聊天正文 |

工程依赖仅声明文本收发需要的二维码库与开发工具；独立 chat 不依赖额外 SDK。chat 离线结构检查仅需 Node.js；完整工程类型检查、Vitest 和编译需已声明的开发依赖。命令见 [README 测试说明](../README.md#测试)。SQLite 驱动尚待选定。未来 DSH、SSH 或 Python 工具不因本技术栈确认而进入首版范围。

当前 iLink 接入对应微信内的机器人会话入口；OpenClaw 官方插件也使用该协议。Weave 独立实现协议客户端，不依赖 OpenClaw 宿主，不因此具备普通微信好友或小号托管能力。当前入口形态与验收边界以首版方案为准。

## 接入依据与适用范围

- 微信接入依据：[腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)、[请求实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts)、[二维码登录实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts)。当前线协议兼容参考为腾讯插件 2.4.10；代码独立实现最小文本客户端。协议字段存在不等于服务端保证，真实收发需要单独验收。
- 腾讯参考项目为 MIT 许可证。当前不安装或复制整个 OpenClaw 插件；协议差异集中在渠道层，后续替换渠道实现时应用策略与测试接口保持独立。
- DeepSeek 接入按官方 Chat Completions、Tool Calls 及 Search／Fetch HTTP 接口实现；具体依据见 [chat 模块](../src/chat/L2.md#接口依据)，真实样本的验证记录与未覆盖边界见 [项目交接](交接文档.md#3-验证与已知问题)。使用模拟 HTTP／模型的自动测试已按用户要求删除；默认工程检查保留纯逻辑与实际终端测试，真实验收由 `npm run test:api` 单独触发。
- npm 依赖来源为公共 registry.npmjs.org。实际依赖树及版本由锁文件维护，安装时不运行依赖生命周期脚本。
