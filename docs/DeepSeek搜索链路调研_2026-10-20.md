# DeepSeek 搜索链路与 Weave 可行性调研

> 仓库携带版：2026-10-21，同步原工作区同名文档并调整相对链接。当前实现以源码与 Git 版本为准。

核对日期：2026-10-20。本文是公开资料与源码调研，不是官网实测报告，也不改变 Weave 已确认的首版范围。

## 结论

可以针对明确任务设计比通用聊天更适合自己的搜索问答流程，但目前没有对照数据证明其优于 DeepSeek 官网。值得比较的方向是：中日文官方资料核查、版本与日期辨别、关键结论逐项给出证据，以及微信里的简洁呈现。

本次能直接阅读的是官方 Search／Fetch 文档和 DeepSeek Harness 的搜索工具源码。Harness 是官方开源的 Agent 产品，不等于 `chat.deepseek.com` 官网聊天；不能将其参数、提示词或策略直接当作官网实现。

## 官方 Harness 的可见做法

以下均属于所查阅的 Harness `master` 源码与文档，分支内容会变化。

1. **给模型搜索和抓取两种工具。** 模型提交 `queries` 数组；默认一次最多 4 个查询，最终返回来源默认最多 8 条。这里的上限是部署配置，不是官网的已知限制。[S3]
2. **程序负责执行与结果整理。** 相同查询只执行一次；不同查询并发执行；按各查询排名轮流取结果、按 URL 去重，再应用返回数量上限。这个合并步骤本身不是已公开的语义重排算法。[S3]
3. **需要全文时再抓页面。** 抓取工具接收 URL；对于返回的 HTML，会移除脚本和隐藏内容，再转换成 Markdown，并限制输出长度。[S4]
4. **把来源带回模型。** 搜索结果携带标题、URL、可用摘要和日期；工具指引要求按需抓全文并引用 URL，同时把网页内容作为外部数据处理。[S3–S4]

这说明官方公开方案已经超过“搜一次，把列表拼给模型”。单纯增加多关键词、去重和全文抓取，不足以证明超过官网。

## Search 接口已经提供什么

Search 的 `query` 支持站点、语言、日期等筛选；`ori_question` 可以附带原问题。结果包含排序分、标题、链接、短摘要 `snippet`、长摘要 `summary`、可选正文 `content`、日期和权威等级等信息。[S2]

这些字段有助于筛选和组织证据，但分数高不等于事实必然正确，来源链接存在也不等于该页面支持答案中的每个结论。关键判断仍需阅读正文与检查版本、适用范围。

Harness 的独立 Search 适配器当前发送 `need_content: false`，将返回结果转换为来源清单，主要保留标题、URL、短摘要和日期；它并未直接把接口的全部长摘要、正文和评分都交给模型。这是可调整的设计点，增加正文也会增加输入量，不能据此认定一定更好。[S5]

## 关于 Flash 云端搜索的补充更正

此前会话把托管搜索主要归于 Pro 的 Responses 路径，范围说窄了。官方 Harness 的另一适配器通过 Anthropic 兼容 Messages 接口启用 `web_search_20250305`，默认模型名为 `deepseek-v4-flash`。代码解析结构化搜索结果与引用摘录，并将其转换为来源数据；普通回答文本不作为搜索结果来源。[S6]

因此，不能笼统说 Flash 没有任何云端托管搜索路径。“普通 Chat Completions 不自动搜索”与“其他协议存在服务端搜索工具”可以同时成立。本次没有使用真实 Key 调用该路径；实施前需确认当前模型映射、账户可用性、返回结构与费用。

## 我们值得做的候选流程

这部分是建议设计，不是对官网缺陷的认定，也不是已实施功能：

```text
明确原问题和需要核实的事实
→ 按需生成中／日／英文查询，优先查官方来源
→ 搜索并合并、去重
→ 对关键结论抓取原文，核对发布时间、版本与适用范围
→ 发现冲突或缺证时有界补搜
→ 写出结论，并把证据链接对应到具体判断
→ 输出适合微信阅读的答案
```

应先用简单流程建立基线，再根据实际失败增加步骤。无需预先增加多个模型、向量库或通用 Agent 框架；搜索、抓取与回答整合保持可替换的职责边界。

## 怎样验证是否更好

建议先选 20 个真实问题，覆盖版本对比、官方技术资料、日本本地资料和来源互相冲突的情况。固定原问题、时间范围与回答要求，对比官网联网搜索和候选实现；记录模型标识、搜索模式、预算、时间及原始来源。

人工逐项检查关键事实正确率、引用是否实际支持对应结论、资料是否适用当前版本、是否漏掉重要条件，并记录耗时与费用。不要仅靠模型自评、回答长度或引用数量判断胜负。样本可重复运行，先报告该任务集上的结果；没有足够证据时不外推为全面超过官网。
