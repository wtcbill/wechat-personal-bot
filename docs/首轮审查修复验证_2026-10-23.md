## 受控真实 API

使用现有本机配置，所有 HTTP 真正转发到 DeepSeek。观察实际模型输入策略、决定类型、工具执行计数与 HTTP 状态；不以答案自称已搜索作为证据。不打印密钥、请求头或 reasoning_content。

`npm.cmd run test:review-api` 最终完整运行通过：

| 样本 | 实际策略／行为 |
|---|---|
| 未传 network，解释搜索算法 | auto；无 Search／Fetch，进入思考作答 |
| 未传 network，今天有什么新闻 | auto；实际执行 Search，取得 summary，思考作答带本轮引用；仅验证搜索决定与调用，不验新闻日期和事实准确性 |
| 显式 auto，翻译“不要联网” | auto；识别为翻译对象，无工具调用 |
| auto，不需要搜索并润色 | auto；无工具调用或 supplement 决定 |

| 显式 required，读取官方页并保留锚点 | 实际 Fetch HTTP 200；来源从 unread 变 read；completed 答案保留 #enable-thinking，无额外补查 |

同一脚本还直接执行真实 Research：Search 后目录为 summary，读取指定页后为 read，再读使用缓存、不增加 Fetch；以本轮来源构造新 Research 后全部为 unread，evidence() 为空。四种状态的完整覆盖由离线投影回归完成；不为制造 failed 状态而调用无效外部网页。

`npm.cmd run test:api` 最终完整运行通过：直接日语翻译、同会话追问、独立路由到 chat 的 Search＋Fetch 及思考作答；三项均 completed，相关 HTTP 均为 200，搜索用例返回已读取来源和内部引用。

本轮还观察到一个 auto 新闻样本请求一次 supplement 并成功完成追加搜索和作答；这仅是该样本的真实路径，不代表补查全部异常分支已验收。

## 保留限制

- 通用 required 澄清仍有文案识别限制：单独输入“请查询天气。”时，真实检索选择 clarify，但后续作答被现有外部证据／澄清检查拒绝，最终 limited。固定提问样本仅证明现有通路可达，不代表任意澄清文案通过。该限制未在 B1–B4 中修复。
- 未注入统一当前日期／时区。新闻样本出现将 10 月 22 日称为今天的答案，与本轮日本日期 10 月 23 日不一致；本次只验模型会搜索，不认定时效答案正确。时间上下文继续按原审查记录另行处理。
- 原文网址翻译误拦截、上下文预算、输入上限衔接、微信交互和旧产物清理未处理；没有新做微信手机验收。
- 不保证锚点存在或来源在语义上支持每项结论；没有量化模型误判率或 B4 对重复调用、耗时与费用的改善。
