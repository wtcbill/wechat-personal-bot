# 个人微信 AI Bot

用于个人微信账号的私聊 AI 助手，响应所有用户的私聊文本，无本人身份验证。支持多轮文本对话、本地 Ollama 和兼容 chat completions 的模型接口；配置多个模型时按顺序尝试。

## 功能

- 处理所有用户的私聊文本，回复原发送者；忽略群消息、公众号、自身消息和非文本消息。
- 按接收顺序处理消息，避免同一会话并发修改上下文；重复消息 ID 不重复处理。
- 上下文按发送者隔离，仅保留在内存中，按完整问答轮次限制长度；重置只清空当前私聊，重启清空全部会话。
- 支持帮助、重置会话、查看上下文轮数；长回复分段发送。
- 不包含积分、群管理、群记录、旧总结、排行榜、撤回回显、娱乐和定时群推送。

## 环境

- Windows，Python 3.10 或更高版本。
- 微信接入沿用原包的 `wcferry==39.2.4.0`。原资料对应微信 3.9.10.27；本项目未验证这些旧版本在当前环境能否登录或工作。
- 一个已登录的 bot 微信账号，以及与它私聊的用户账号。无需配置用户 ID 或白名单。
- 已经运行的模型服务。项目不安装模型，也不附带微信客户端、Python 环境或 SDK 二进制文件。

微信底层接入集中在 `main.py` 和 `personal_bot/bot.py`；后续更换接入方式可保留独立的对话与模型层。

## 配置

将 `config.example.json` 复制为 `config.local.json`，填写实际模型名称。配置文件路径与启动时的当前目录无关。

默认示例使用 Ollama：

```json
{
  "name": "local",
  "protocol": "ollama",
  "endpoint": "http://127.0.0.1:11434/api/chat",
  "model": "你已安装的模型名称",
  "timeout_seconds": 120
}
```

若使用兼容 chat completions 的服务，将 `models` 中的条目改为：

```json
{
  "name": "remote",
  "protocol": "openai",
  "endpoint": "https://your-provider.example/v1/chat/completions",
  "model": "服务商提供的模型名称",
  "api_key_env": "PERSONAL_BOT_API_KEY",
  "timeout_seconds": 120
}
```

`endpoint` 填完整请求地址。密钥仅通过环境变量提供；`api_key_env` 填变量名称。使用无需密钥的本地兼容服务时，可省略该字段。环境变量缺失时该模型调用失败，若有备用模型则继续尝试。

`models` 可填写多个条目，以列表顺序决定调用优先级。备用模型会收到同一会话的上下文，请只配置你愿意用于处理这些内容的服务。

`max_history_turns` 控制保留的完整问答轮次（默认 20）；`max_message_chars` 限制单条输入字符数（默认 12000）；`reply_chunk_chars` 控制单段微信回复字符数（默认 1500）。这里的限制按字符计算，不是模型 token 预算；如超出模型上下文容量，应减少历史轮次或缩短输入。

## 检查与启动

在已准备好依赖的环境中运行：

```powershell
python -B main.py --check
python -B main.py
```

`--check` 只校验配置格式与必填项，不加载微信 SDK、不验证网络、模型名称或密钥有效性。缺少有效配置时直接退出，不接收消息。

尚未准备依赖时，需自行安装 `requirements.txt` 中的包；现有本地整合包的 Dlab 环境已有对应 wcferry，但是否可以直接使用仍需在本机验证。本次精简没有安装或升级任何依赖。

## 私聊命令

| 命令 | 功能 |
| --- | --- |
| `/help`、`帮助` | 显示帮助 |
| `/reset`、`新建会话`、`清空上下文` | 清空当前对话上下文 |
| `/status` | 查看内存中保留的问答轮数 |
| 其他文字 | 交给模型处理 |

旧版“总结”等文字没有专用处理器，作为普通对话传给模型。未来如有需要，再单独设计总结等扩展功能。

## 测试

```powershell
python -B -m unittest discover -s tests -v
```

测试使用模拟微信消息和 HTTP 响应，不连接真实微信、调用外部模型或读取旧数据库。真实微信登录、收发和模型服务可用性需要另行验证。

## 数据与限制

项目不保存聊天数据库或完整消息日志，不初始化旧版数据库。`config.local.json`、密钥、日志、数据库和二进制文件都不应提交到仓库。

发送失败时记录不含私聊内容的错误，不自动重发；上下文可能包含已生成但未成功送达的回复。进程内消息去重仅保留最近 1000 个 ID，重启后失效。模型调用为顺序阻塞处理，耗时请求期间后续消息会排队。
